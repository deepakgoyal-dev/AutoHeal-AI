2. Complete System Architecture & Execution Flow

2.1 The Two-Tier Hybrid Philosophy

Most AI hackathon projects fail because they attempt to use LLMs where deterministic algorithms are vastly superior. AutoHeal AI implements a strict separation of concerns across two tiers:

  • Tier 1: Deterministic Statistical & Heuristic Core (Sub-second, Zero-Cost, Ground Truth)
    Cell-by-cell operations (type casting, outlier bounding, median imputation, syntax normalization) are mathematically deterministic. Sending 50,000 cells to an LLM API would cost ~$5.00 per dataset, take 30+ seconds, and risk numeric hallucinations. Tier 1 executes across 405 rows in 0.54 seconds with zero API fees.
  • Tier 2: Semantic Intelligence & Executive Narrative Layer
    Interprets verified statistical outputs ($r$-correlation matrices, skewness distributions, repair density clusters) and translates them into executive-level plain-English briefings and prescriptive directives.

3. The Seven Cleaning Passes: Deep-Dive Mathematical & Algorithmic Analysis

Every member of the team must master the formulas, complexity, edge cases, and failure modes of each pass:

Pass 1: Schema & Header Stabilization

  • File & Line: aegis/healer.py — lines 64–88 (_heal_headers)
  • Algorithm: Regex character filtering and underscore collapse: clean = re.sub(r'[^a-zA-Z0-9_]', '_', col_str.lower()); clean = re.sub(r'_+', '_', clean).strip('_')
  • Complexity: Time: $O(C \cdot L)$ where $C$ is column count and $L$ is string length. Space: $O(C)$ for the rename mapping.
  • Failure Mode / Edge Case: Header Collision. If input data contains both "User Name" and "User_Name", both normalize to "user_name". In Pandas, duplicate column names cause subsequent column selections to return a DataFrame rather than a Series, breaking downstream passes.
  • Engineering Defense: "In production pipelines, we resolve collisions by maintaining a seen set and appending monotonic suffixes (user_name_1, user_name_2)."

Pass 2: Sentinel Null Clearing

  • File & Line: aegis/healer.py — lines 90–112 (_heal_sentinel_nulls)
  • Mathematical Foundation: Missing Data Theory (Donald Rubin, 1976):
    • MCAR (Missing Completely at Random): $P(M | Y_{obs}, Y_{mis}) = P(M)$. Missingness independent of all variables. Imputation is unbiased.
    • MAR (Missing at Random): $P(M | Y_{obs}, Y_{mis}) = P(M | Y_{obs})$. Missingness depends on observable covariates. Group-conditioned imputation minimizes bias.
    • MNAR (Missing Not at Random): $P(M | Y_{obs}, Y_{mis})$ depends on the missing value itself (e.g., high wealth hidden). Any statistical imputation introduces bias.
  • Implementation: Fast lookup against a 25-element hash set $\mathcal{S} = \{ ext{""}, ext{" "}, ext{"-999"}, ext{"n/a"}, ext{"#ref!"}, ext{"??"}, \dots\}$ in $O(1)$ average time per cell. Replaces matches with np.nan.
  • Complexity: Time: $O(N \cdot C)$ across $N$ rows and $C$ columns. Space: $O(N)$ list buffer per column.

Pass 3: Regex Coercion & Format Harmonization

  • File & Line: aegis/healer.py — lines 114–205 (_heal_types_and_formats)
  • Implementation: 1. Inspects a 50-row sample; if $\ge 50\%$ match numeric/currency patterns, triggers numeric coercion. 2. Strips currency glyphs [\$\€\£\¥\₹USDusd\s] and thousands-separators ,. 3. Normalizes percentages (e.g., "15%" $ ightarrow$ 15.0). 4. Evaluates an 11-format datetime cascade (%Y-%m-%d %H:%M:%S, %d/%m/%Y, %m/%d/%Y, unix timestamps).
  • Complexity: Time: $O(N \cdot C \cdot K)$ where $K$ is regex evaluation depth. Space: $O(N)$ for coerced Series.
  • Failure Mode / Edge Case: Date Ambiguity. String "03/04/2024" can represent March 4 (US %m/%d/%Y) or April 3 (UK/India %d/%m/%Y).
  • Engineering Defense: "Our date parser prioritizes international/Indian standard %d/%m/%Y over US %m/%d/%Y. In an enterprise system, date locale must be explicitly supplied in the pipeline configuration."

Pass 4: Fuzzy Categorical Consensus (Ratcliff-Obershelp)

  • File & Line: aegis/healer.py — lines 240–290 (_heal_categorical_typos)
  • Mathematical Formula: Ratcliff-Obershelp (Gestalt pattern matching via difflib.SequenceMatcher):
    $$ ext{Similarity}(S_1, S_2) = rac{2 \cdot K_{ ext{matching}}}{|S_1| + |S_2|}$$
    where $K_{ ext{matching}}$ is the sum of characters in all non-overlapping matching subsegments.
  • Mechanism: Categorical frequencies are split into Canonical Targets ($freq \ge \max(3, 0.04 \cdot N)$) and Errant Candidates ($freq < ext{threshold}$). If similarity $\ge 0.80$, maps typo to canonical target.
  • Complexity: Worst-case $O(U_{ ext{errant}} \cdot U_{ ext{canonical}} \cdot L^2)$ where $U$ is unique count and $L$ is string length.
  • Failure Mode / Edge Case: Short-string semantic collisions. Comparing "Male" ($|S_1|=4$) vs "Female" ($|S_2|=6$): $K_{ ext{matching}} = 4$ (substring "male"). $ ext{Ratio} = rac{2 \cdot 4}{4 + 6} = rac{8}{10} = 0.80$. At a global threshold of 0.80, "Female" matches "Male"!
  • Engineering Defense: "This demonstrates why global thresholds are dangerous. In production, we require token-length-weighted thresholds or absolute edit distance bounds (Levenshtein $\le 1$) for strings where $|S| \le 5$."

Pass 5: Skewness-Aware Adaptive Imputation

  • File & Line: aegis/healer.py — lines 292–387 (_heal_missing_values)
  • Mathematical Formula: Fisher-Pearson standardized sample skewness $G_1$:
    $$m_2 = rac{1}{n}\sum_{i=1}^n (x_i - ar{x})^2, \quad m_3 = rac{1}{n}\sum_{i=1}^n (x_i - ar{x})^3$$ $$G_1 = rac{m_3}{m_2^{3/2}} \cdot rac{\sqrt{n(n-1)}}{n-2}$$
  • Statistical Decision Boundary:
    • If $|G_1| < 0.5$: Distribution is approximately symmetric. Imputes sample mean $ar{x}$ (minimizes Mean Squared Error: $rg\min_c \sum (x_i - c)^2$).
    • If $|G_1| \ge 0.5$: Distribution is skewed. Imputes sample median $ ilde{x}$ (minimizes Mean Absolute Error: $rg\min_c \sum |x_i - c|$).
    • Group-Conditioned Median: If a low-cardinality categorical feature exists ($2 \le ext{cardinality} \le 15$), imputes $ ilde{x}_{ ext{group}} = ext{median}(x \mid ext{category} = k)$ to preserve intra-cluster variance.
    • Categorical Mode: Categorical missingness is imputed with the dominant population mode.
  • Complexity: Skewness computation: $O(N)$. Median sorting: $O(N \log N)$. Overall: $O(N \log N)$ per column.

Pass 6: Non-Parametric IQR Outlier Winsorization

  • File & Line: aegis/healer.py — lines 389–450 (_heal_outliers)
  • Mathematical Formula: John Tukey's Fences (1977):
    $$ ext{IQR} = Q_3 - Q_1$$ $$ ext{Lower Fence} = \max\Big(0.0, \; Q_1 - 1.5 \cdot ext{IQR}\Big) \quad ext{(enforces non-negativity if } X \ge 0 ext{)}$$ $$ ext{Upper Fence} = Q_3 + 1.5 \cdot ext{IQR}$$ $$ ext{Winsorization: } x_{ ext{healed}} = egin{cases} ext{Upper Fence} & ext{if } x > ext{Upper Fence} \ ext{Lower Fence} & ext{if } x < ext{Lower Fence} \ x & ext{otherwise} \end{cases}$$
  • Mathematical Proof for 1.5 Multiplier: For a normal distribution $\mathcal{N}(\mu, \sigma^2)$, $Q_1 = \mu - 0.6745\sigma$, $Q_3 = \mu + 0.6745\sigma$. Thus $ ext{IQR} = 1.349\sigma$. $$ ext{Upper Fence} = \mu + 0.6745\sigma + 1.5(1.349\sigma) pprox \mu + 2.698\sigma pprox \mu + 2.7\sigma$$ Under Gaussian assumptions, $\mu \pm 2.7\sigma$ encloses $99.3\%$ of the distribution, flagging only the extreme $0.7\%$ tails.
  • Why Winsorize instead of Dropping? Dropping a row because one sensor spiked deletes legitimate data across the other 10 features. Winsorizing preserves sample size $N$ while bounding extreme leverage in downstream regressions.
  • Complexity: Quantile computation: $O(N \log N)$ or $O(N)$ with Quickselect. Capping pass: $O(N)$.

Pass 7: Exact Record Deduplication

  • File & Line: aegis/healer.py — lines 452–471 (_heal_duplicates)
  • Mechanism: Evaluates complete row tuple equality via df.duplicated(keep='first'). Logs row removals into the ledger and resets row indexing.
  • Complexity: Time: $O(N \cdot C)$ utilizing hash table row hashing. Space: $O(N)$ bitmask.
  • Failure Mode / Edge Case: Legitimate repeated transactions. Two cash transactions for \$5.00 at 12:00 PM without a primary key look identical to a hash set, risking the deletion of real business events.

6. The Master Hackathon Defense: 18 Judge Questions & Model Answers

Q1: Why use deterministic statistical methods instead of an LLM to clean every cell?
Deepak (Lead): "We evaluated both architectures and found three fatal bottlenecks with pure LLMs for tabular cleaning: (1) Latency: Calling an LLM API row-by-row on a 10,000-row table takes over 15 minutes; our statistical engine cleans it in under 0.6 seconds. (2) Economic Cost: Feeding tabular tokens into commercial LLMs costs ~$5 per dataset; statistical heuristics run locally at zero cost. (3) Hallucination Risk: LLMs are probabilistic text generators. In financial or clinical data, an LLM might invent plausible-sounding values. Deterministic IQR bounds and median imputation guarantee mathematically reproducible, auditable results."
Q2: How do you decide between mean, median, and group-conditioned median imputation?
Rudra (Data Science): "We compute the Fisher-Pearson sample skewness $G_1$. If $|G_1| < 0.5$, the distribution is approximately symmetric, and we impute the sample mean, which minimizes Mean Squared Error. If $|G_1| \ge 0.5$, the distribution is skewed, and we impute the median, which minimizes Mean Absolute Error and is robust to extreme outliers. Furthermore, if a low-cardinality categorical column exists (e.g., product_category), we compute group-conditioned medians $ ilde{x}_{ ext{group}}$ to preserve intra-cluster variance rather than collapsing the entire feature into a single global median."
Q3: What does skewness measure, and why is your threshold of 0.5 appropriate?
Rudra (Data Science): "Skewness measures the asymmetry of the probability distribution about its mean. It is the standardized third central moment $m_3 / m_2^{3/2}$. A threshold of $|s| < 0.5$ is the standard Bulmer threshold in statistical literature for approximately symmetric distributions where the mean and median closely coincide. Beyond 0.5, using the mean introduces severe bias because the mean is dragged in the direction of the tail."
Q4: How are Q1 and Q3 computed, and why use 1.5 × IQR?
Deepak / Rudra: "We compute $Q_1$ and $Q_3$ using linear percentile interpolation at 25% and 75%. John Tukey established the $1.5 \cdot ext{IQR}$ fence for boxplots. Mathematically, for a Gaussian distribution $\mathcal{N}(\mu, \sigma^2)$, $ ext{IQR} = 1.349\sigma$. Adding $1.5 \cdot ext{IQR}$ to $Q_3$ yields $\mu + 2.7\sigma$. In a normal distribution, $\pm 2.7\sigma$ covers 99.3% of all observations. Thus, the 1.5 multiplier ensures that only the extreme 0.7% tail is treated as an anomaly, minimizing false positive outlier detection."
Q5: How do you distinguish a genuine outlier from a corrupted value?
Deepak (Lead): "Statistically, an algorithm cannot know semantic intent without domain context. This is why we winsorize rather than drop. Dropping assumes the value is corrupt, which discards valid rows. Winsorizing caps the observation at the 1.5 IQR boundary limit. If a transaction is legitimate high-value, its record remains intact, but its extreme leverage on downstream variance and ML gradients is bounded. In our enterprise design, we also support an explicit flag_only mode that sends values exceeding $3.0 \cdot ext{IQR}$ to a human-in-the-loop review queue."
Q6: What similarity algorithm is actually used for category correction?
Deepak / Nikhil: "We use Python's standard library difflib.SequenceMatcher, which implements the Ratcliff-Obershelp (Gestalt pattern matching) algorithm. It finds the longest common contiguous matching subsegments recursively and computes the ratio $2M / (T_1 + T_2)$. We selected it because it runs in standard Python with zero external C-dependencies, making deployment seamless across Windows, Linux, and Docker."
TRAP WARNING: If you say Levenshtein distance, a judge will ask for the dynamic programming recurrence matrix. Admit Ratcliff-Obershelp upfront!
Q7: How do you prevent fuzzy matching from merging distinct categories (e.g., Male vs Female)?
Deepak / Nikhil: "That is a real failure mode of global character ratio metrics: 'Female' contains 'Male' as a substring ($K=4$), yielding a 0.80 ratio. To prevent semantic merging of distinct classes: (1) We require a minimum frequency gap—targets must represent dominant canonical categories ($freq \ge 4\%$), while candidates must be rare typos ($freq < 4\%$). (2) In our roadmap, we enforce absolute Levenshtein distance thresholds ($\le 1$) for tokens with length $\le 5$."
Q8: What happens when two headers normalize to the same name?
Deepak (Lead): "If a dataset has 'User Name' and 'User_Name', both normalize to 'user_name'. In our current code, this generates duplicate column headers in Pandas. In a production pipeline, our planned collision resolution maintains a dictionary of seen normalized names and appends a sequential index: user_name, user_name_1."
Q9: How do you handle ambiguous dates such as 03/04/2024?
Nikhil (Ingestion): "In our _parse_flexible_date routine, we evaluate format patterns sequentially. %d/%m/%Y precedes %m/%d/%Y, so it parses as April 3. However, statistical code cannot guess geography. For true enterprise safety, locale configuration must be injected upfront (e.g., date_locale='en_US' vs 'en_GB') rather than guessing."
Q10: How do you prove the health score improved data quality rather than just completeness?
Deepak (Lead): "Our health score formula does not just count missing cells. Completeness is only 35% of the score. 30% is allocated to Syntactic Validity (currency glyph stripping, decimal conversion, header hygiene), 20% to Outlier Reasonableness (bounding high-leverage spikes), and 15% to Uniqueness. If an engine simply filled nulls with zeros, the validity and outlier components would penalize it. A score above 95 requires simultaneous cleanliness across all four dimensions."
Q11: How do you validate imputed values when the true values are unknown?
Rudra (Data Science): "In unsupervised production runs, ground truth is unavailable by definition. We validate imputation quality by measuring distribution preservation: we compare the Kolmogorov-Smirnov (KS) statistic and Wasserstein distance between the observed distribution and the imputed distribution. Imputation is considered valid if it preserves the empirical cumulative distribution function (ECDF) without introducing artificial variance spikes."
Q12: What exactly is stored in the ledger, and can it be tampered with?
Deepak (Lead): "Our ledger is an in-memory audit log of HealingAction dataclasses recording timestamp, row index, column name, issue type, original value, healed value, strategy, and confidence score. It is an audit trail, not a cryptographically signed blockchain. In our enterprise deployment roadmap, we serialize these action logs with SHA-256 block chaining to ensure tamper-evidence."
